Proof 1: Lossless-Join Decomposition Verification ($R_1 \bowtie R_2 = R$)
Lossless Property Theorem
Formal Theorem:

A decomposition of relation schema $R$ into $R_1$ and $R_2$ ($R = R_1 \cup R_2$) is lossless with respect to functional dependency set $F$ if and only if:

$$\Pi_{R_1}(r) \bowtie \Pi_{R_2}(r) = r$$

This holds if and only if the intersection of the decomposed relations functionally determines either $(R_1 \setminus R_2)$ or $(R_2 \setminus R_1)$ in the closure $F^+$:

$$(R_1 \cap R_2) \to (R_1 \setminus R_2) \in F^+ \quad \text{OR} \quad (R_1 \cap R_2) \to (R_2 \setminus R_1) \in F^+$$
Case Study: Decomposition of Equipment and Categories ($R_{\text{EC}} \to R_{\text{equip}}, R_{\text{cat}}$)

Let relation $R_{\text{EC}}$ and dependency set $F$ be defined as:

R_EC = {equipment_id, asset_tag, name, cost, category_id, category_name, description}
F = { {equipment_id} → {asset_tag, name, cost, category_id}, {category_id} → {category_name, description} }

Decompose $R_{\text{EC}}$ into:

  • $R_1 = \{\text{equipment\_id}, \text{asset\_tag}, \text{name}, \text{cost}, \text{category\_id}\}$
  • $R_2 = \{\text{category\_id}, \text{category\_name}, \text{description}\}$
Step-by-Step Attribute Closure Algorithm:
  1. Calculate Intersection: $R_1 \cap R_2 = \{\text{category\_id}\}$
  2. Calculate Relative Complements:
    • $R_1 \setminus R_2 = \{\text{equipment\_id}, \text{asset\_tag}, \text{name}, \text{cost}\}$
    • $R_2 \setminus R_1 = \{\text{category\_name}, \text{description}\}$
  3. Compute Attribute Closure of Intersection under $F$:
    X^(0) = {category_id}
    Apply {category_id} → {category_name, description}:
    X^(1) = {category_id, category_name, description}
    Hence, {category_id}^+_F = {category_id, category_name, description} = R_2
Q.E.D. Verification: Since $(R_2 \setminus R_1) \subseteq \{\text{category\_id}\}^+_F$, it follows directly that: $$(R_1 \cap R_2) \to (R_2 \setminus R_1) \in F^+$$ The common attribute $\{\text{category\_id}\}$ is a superkey of $R_2$. Therefore, the decomposition is strictly Lossless.
Proof 2: Dependency Preservation Analysis ($F' \equiv F$)
Dependency Preservation Theorem
Formal Theorem:

A decomposition $D = \{R_1, R_2, \dots, R_k\}$ preserves functional dependency set $F$ if:

$$F' = \bigcup_{i=1}^k \pi_{R_i}(F) \quad \text{satisfies} \quad (F')^+ = F^+$$

This ensures every functional dependency can be verified at insertion or update time by inspecting only a single relation, without evaluating expensive relational joins.

Original Functional Dependency ($X \to Y \in F$) Host Table ($R_i$) Projection Verification ($\pi_{R_i}(F)$) Enforcement Mechanism Status
{equipment_id} → {asset_tag, cost, status} equipment X ∪ Y ⊆ equipment PRIMARY KEY Preserved
{asset_tag} → {equipment_id} equipment X ∪ Y ⊆ equipment UNIQUE (asset_tag) Preserved
{lab_id} → {department_id, lab_name, room} laboratories X ∪ Y ⊆ laboratories PRIMARY KEY Preserved
{borrowing_id} → {equipment_id, user_id, date} borrowings X ∪ Y ⊆ borrowings PRIMARY KEY Preserved
{user_id} → {email, role_id, department_id} users X ∪ Y ⊆ users PRIMARY KEY Preserved
Formal Result: All non-trivial functional dependencies in $F$ are fully preserved in the local table schemas. The decomposition is 100% Dependency Preserving.
Proof 3: Minimal Cover ($F_c$) Algorithmic Derivation
Canonical Cover Algorithm

A minimal cover $F_c$ is an equivalent irreducible set of functional dependencies where all right-hand sides are single attributes, no left-hand sides contain extraneous attributes, and no dependencies are redundant.

f1: equipment_id → asset_tag
f2: equipment_id → name
f3: equipment_id → status
f4: {equipment_id, asset_tag} → status
f5: {equipment_id, asset_tag} → cost
f6: asset_tag → equipment_id
f7: user_id → email
f8: {user_id, email} → role_id

An attribute $B \in X$ is extraneous in $X \to A$ if $A \in (X \setminus \{B\})^+_F$:

Testing f4: {equipment_id, asset_tag} → status:
Compute {equipment_id}^+_F. By f3, status is derived.
→ asset_tag is extraneous and removed! Reduces to: equipment_id → status.

Testing f8: {user_id, email} → role_id:
Compute {user_id}^+_F. By f7, user_id → email.
→ email is extraneous and removed! Reduces to: user_id → role_id.

A dependency $X \to A$ is redundant if $A \in X^+_{F \setminus \{X \to A\}}$:

- Reduced f4 (equipment_id → status) is an exact duplicate of f3. Pruned!
- Reduced f8 (user_id → role_id) is an exact duplicate of primary role link. Pruned!

Final Irreducible Canonical Cover Set:
$$\boxed{ F_c = \begin{cases} \text{equipment\_id} \to \{\text{asset\_tag}, \text{name}, \text{cost}, \text{status}\} \\ \text{asset\_tag} \to \{\text{equipment\_id}\} \\ \text{user\_id} \to \{\text{first\_name}, \text{email}, \text{role\_id}\} \\ \text{borrowing\_id} \to \{\text{equipment\_id}, \text{user\_id}, \text{borrow\_date}, \text{status}\} \\ \{\text{equipment\_id}, \text{borrow\_date}\} \to \{\text{borrowing\_id}\} \end{cases} }$$
